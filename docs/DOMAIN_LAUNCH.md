# MILLER: millervisual.ru

Этот файл готовит переключение GitHub Pages на уже зарегистрированный у Beget домен. Пока DNS Beget не направлен на GitHub Pages, изменения этой ветки не следует публиковать в `main`: файл `CNAME` переключает адрес сайта.

## DNS в Beget

Оставить DNS-серверы Beget. В разделе DNS для корня `millervisual.ru` удалить A-запись хостинга Beget и добавить четыре A-записи:

- `185.199.108.153`
- `185.199.109.153`
- `185.199.110.153`
- `185.199.111.153`

Создать подзону `www` и CNAME `www` → `stepanmiller.github.io`. Если для `www` есть другие A/AAAA/CNAME, удалить конфликтующие. Не менять MX-записи почты.

После обновления DNS опубликовать эту ветку в `main`. В GitHub Settings → Pages проверить Custom domain `millervisual.ru` и после выдачи сертификата включить Enforce HTTPS. Проверить `https://millervisual.ru/`, `https://www.millervisual.ru/`, интерактивные работы `cases/heart/` (включая смену слайдов) и `cases/bali/`, видео и кнопку MAX.

## Подготовка к Яндекс.Директ

Перед рекламой создать счётчик Яндекс Метрики для `millervisual.ru`, установить его код на сайт, затем записать номер счётчика в `data-metrika-id` на теге `<html>`. Создать две цели «JavaScript-событие» с точными именами `max_contact_click` и `brief_prepared`; протестировать их в Метрике. Они показывают намерение посетителя: переход в MAX и подготовку текста. Число реально полученных заявок сверять с входящими сообщениями MAX, не называть клики заявками.

Привязать этот счётчик к кампании Яндекс.Директ, добавить параметры ссылок `utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_name}`. Сначала проверить открытие страниц и события цели с тестового объявления, затем запускать бюджет.
